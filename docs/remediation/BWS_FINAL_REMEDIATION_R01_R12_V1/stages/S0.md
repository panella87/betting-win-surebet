
# S0: Admission and immutable campaign freeze

## Stage objective

Freeze exact campaign authority without application-source mutation and prepare a non-active one-tranche admission.

## Ordered tranche list

- none; S0 is admission authority rather than a remediation tranche

## Entry gate

Exact BWS122 and planning artifacts validated; current queue/controller/holds unchanged.

## Exit gate

An explicit campaign authority must name BWS122, one active tranche, allowed paths, protected automation allowance where applicable, and unchanged BWS holds.

## Why order matters

- S0 precedes every source mutation because it establishes immutable authority and one-tranche admission.

## Primary owners

- S0 admission authority

## Shared paths and serialization points

- none inside S0; protected authority remains read-only

Every shared path requires the prior owning tranche postimage, one active edit owner, read-only secondary reviewers, and a postimage handoff before the next owner is admitted.

## Required proof environments

- authority/documentation proof only

## Expected artifacts and receipts

- stage admission or S0 proposal receipt;
- one preimage, current-source reverification, postimage, focused-test, production-entrypoint, and environment receipt per admitted tranche as applicable;
- rollback receipt for any reverted or interrupted cycle;
- one stage-result receipt binding all terminal tranche receipts;
- retained-hold register and next-stage admission decision.

## Rollback and interruption behavior

Stop new writes, classify the active tranche as `BLOCKED` unless an exact rollback completes, restore every changed byte/mode from the admitted preimage, remove only transaction-owned additions, preserve unrelated dirty content, and record ambiguity rather than inferring success. No later tranche may start from an unreceipted or mixed postimage.

## External blockers that may remain

- Git checkout fields remain TO_CAPTURE_AT_ACTIVATION.

## Prohibited promotion behavior

- no documentation, source completion, static marker, unexecuted test, Node 22 run, fixture, mock, local export, declaration, or caller assertion promotes a hold;
- `SOURCE_COMPLETE_EXTERNAL_PENDING` does not admit the next release/deployment/live-execution state;
- S1 and S2 do not use existing autonomous controllers;
- no access to or mutation of `betting-win` is authorized.

## Holds after stage completion

```text
BWS-600=BLOCKED
BWS-710=BLOCKED
BWS-900=PARKED_NOT_AUTHORIZED
release=BLOCKED
deployment=BLOCKED
live_execution=PROHIBITED
```

A separate explicit, evidence-bound decision is required to change any hold.

## Exact next-stage admission rule

After this stage's exit receipt validates, admit exactly the first not-yet-terminal tranche of S1; bind the accepted predecessor postimage, dependencies, exact allowed paths, proof environments, and retained holds. If no such receipt exists, remain `BLOCKED`.
